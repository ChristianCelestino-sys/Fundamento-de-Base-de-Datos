
# 📚 Unidad 2: Diseño de Bases de Datos con el Modelo E-R

## 🎯 Competencia específica

Conocer y aplicar el modelo Entidad-Relación (E-R) para el diseño conceptual de bases de datos, con el propósito de organizar la información y atender las necesidades del entorno.

---

## 📂 Contenido de la unidad

En esta unidad se desarrollan dos actividades principales:

1. **Tarea 2.1:** Modelado conceptual E-R y E-R Extendido de un caso real.
2. **Tarea 2.2:** Transición de diagrama E-R a notación UML.

---

# 📝 Tarea 2.1: Modelado conceptual E-R y E-R Extendido de un caso real

## 📌 Objetivo

Diseñar un modelo conceptual de base de datos a partir de un caso real, identificando las entidades, sus atributos, las relaciones y las restricciones del sistema. También se aplican los conceptos del modelo E-R Extendido.

## 📋 Actividades realizadas

- Seleccionar un caso de estudio o una problemática real.
- Describir el contexto del problema.
- Identificar y documentar las reglas de negocio.
- Definir las entidades y sus atributos.
- Identificar claves primarias y atributos compuestos, derivados y multivalorados, cuando correspondan.
- Establecer las relaciones entre entidades.
- Determinar las cardinalidades y restricciones de participación.
- Aplicar especialización, generalización, jerarquías y agregación cuando sean pertinentes.
- Elaborar el diagrama formal mediante una herramienta de modelado.

## 📄 Entregables

1. **Reporte técnico en PDF**, que incluya:
   - Planteamiento del problema.
   - Descripción del caso de estudio.
   - Reglas de negocio.
   - Diagrama E-R o E-R Extendido en alta resolución.
   - Justificación del diseño.

2. **Repositorio público de GitHub**, con:
   - Archivo fuente editable del diagrama (`.drawio`, `.erwin` o `.xml`).
   - Diagrama exportado como imagen o PDF.

3. **Video público de YouTube**, donde se explique:
   - La problemática real seleccionada.
   - Las reglas de negocio.
   - La formulación y defensa del diagrama E-R.
   - La captura de pantalla del trabajo, con la cámara web visible en la esquina inferior derecha.

# 📝 Tarea 2.2: Transición de diagrama E-R a notación UML

## 📌 Objetivo

Transformar el diagrama conceptual E-R elaborado en la Tarea 2.1 en un diagrama de clases utilizando la notación UML, estableciendo la correspondencia entre las entidades, sus atributos y sus relaciones.

## 📋 Actividades realizadas

- Tomar como base el diagrama conceptual E-R de la Tarea 2.1.
- Convertir las entidades en clases UML.
- Relacionar los atributos de las entidades con las propiedades de las clases.
- Representar las relaciones mediante asociaciones.
- Identificar y representar composición, agregación y herencia cuando correspondan.
- Analizar las coincidencias y diferencias entre el modelo E-R y UML.

## 📄 Entregables

1. **Documento PDF**, que contenga:
   - Comparativa detallada entre E-R y UML.
   - Correspondencia entre entidades y clases.
   - Correspondencia entre atributos y propiedades.
   - Correspondencia entre relaciones y asociaciones.
   - Análisis de coincidencias para el desarrollo orientado a objetos.

2. **Repositorio público de GitHub**, con:
   - Diagrama UML editable.
   - Diagrama UML exportado a PDF.

3. **Video público de YouTube**, donde se explique:
   - La transformación del modelo E-R a UML.
   - La correspondencia entre entidades y clases.
   - La correspondencia entre atributos y propiedades.
   - Las asociaciones, la composición, la agregación y la herencia utilizadas.

**Durante la exposición, la cámara web debe permanecer visible en la esquina inferior derecha.**
